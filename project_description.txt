# PharmaVerse

## Generative World Models, Digital Twins, Synthetic Data, and Physical AI for Pharmaceutical Manufacturing

### 1. Project Overview

**PharmaVerse** is a simulation and artificial intelligence research project designed to investigate how generative world models, digital twins, computer vision, synthetic data, and Physical AI can be applied to pharmaceutical manufacturing environments.

The project will create a virtual pharmaceutical manufacturing environment that can be used to simulate manufacturing scenarios that would otherwise require access to physical production equipment, dedicated laboratory space, manufacturing facilities, or large manually annotated datasets.

**World Labs is a defining technology of PharmaVerse, not an optional environment-generation tool.**

The practical system that can be built today is:

**World Labs Marble / World API → OpenUSD → NVIDIA Omniverse / Isaac Sim → synthetic data → computer vision → Sim2Real → Physical AI**

PharmaVerse will use **World Labs Marble and the public World API** as the core world-generation layer, then use **NVIDIA Omniverse/OpenUSD and NVIDIA Isaac Sim** as the controlled simulation layer. Computer vision, synthetic data generation, and Physical AI experiments are built on top of that stack.

Atlas, World Labs' next-generation omni world model, is **not generally available** at the time of this plan. World Labs describes Atlas as entering early access with select partners, and Marble remains the generally available product with a public World API. PharmaVerse is therefore designed to **start on Marble now** and **adopt Atlas later** without changing the rest of the architecture.

The project is intended as a **research, simulation, and engineering prototype**. It is not intended to represent a validated GMP manufacturing system or replace qualified pharmaceutical manufacturing, quality, safety, or regulatory processes.

---

# 2. Central Research Question

The primary research question is:

> **Can generative world models and physics-based simulation be combined to create useful pharmaceutical manufacturing environments for generating synthetic computer vision data, evaluating AI inspection systems, and developing Physical AI applications?**

That question now has an explicit technology form:

> **Can World Labs Marble generate pharmaceutical manufacturing worlds that NVIDIA Omniverse and Isaac Sim can turn into simulation-ready environments for synthetic inspection data and Physical AI research?**

A secondary research question will investigate Sim2Real performance:

> **Can computer vision models trained primarily or partially on synthetic pharmaceutical manufacturing data generalize to real-world imagery?**

These questions make PharmaVerse more than a digital visualization project. The objective is to determine whether the simulated environment can generate **useful data and measurable AI performance**.

---

# 3. Core Architecture: World Labs Generates the World, NVIDIA Simulates It

PharmaVerse adapts an existing **World Labs → NVIDIA simulation pattern** to pharmaceutical manufacturing.

The stack is:

**World Labs Marble / World API**
→ Generate the pharmaceutical manufacturing world

**Marble 3D World**
→ Export world as 3D assets (Gaussian splats, meshes, collider meshes)

**OpenUSD conversion / preparation**
→ Make the generated environment simulation-ready

**NVIDIA Omniverse + Isaac Sim**
→ Add physics, SimReady equipment, sensors, cameras, and controllable objects

**Synthetic Data Generation**
→ RGB + bounding boxes + segmentation + depth + ground truth

**Computer Vision Model**
→ Train pharmaceutical inspection models

**Sim2Real Evaluation**
→ Test against real imagery

**Physical AI**
→ Eventually introduce an autonomous inspection robot

This is not a speculative pipeline. World Labs published a case study with Lightwheel that demonstrated essentially this workflow:

**Real-world input → Marble → 3D Gaussian Splat → NVIDIA Omniverse NuRec → USD → NVIDIA Isaac Sim → SimReady assets → robots/sensors/tasks → simulation/evaluation.**

NVIDIA has also documented the same Marble-to-Isaac-Sim path: export Marble Gaussian splats (PLY) and a collider mesh (GLB), convert the splat to USD with Omniverse NuRec, import into Isaac Sim, then add robots, physics, and sensors.

PharmaVerse applies that pattern to pharmaceutical manufacturing instead of a general robotics test location. A representative Marble generation target is:

> *A modern pharmaceutical packaging suite with stainless-steel equipment, a packaging conveyor, inspection stations, pharmaceutical bottles, cartons, material staging areas and controlled manufacturing architecture.*

Marble can create worlds from **text, images, video, panoramas, multi-image input, or coarse 3D layouts**. It can export Gaussian splats and triangle meshes, including collider meshes intended for coarse physics simulation. The World API makes those generations programmable, which is required for world-level variation and later domain randomization.

# 4. Separated Responsibilities: World Labs vs NVIDIA vs PharmaVerse

Marble should not be expected to generate a perfectly engineered pharmaceutical production line with exact physics and semantic labels. Its role is spatial/world generation. Isaac Sim is the controlled simulation layer.

| Platform                 | PharmaVerse responsibility                    |
| ------------------------ | --------------------------------------------- |
| **World Labs Marble**    | Generate/reconstruct the pharmaceutical world |
| **World API**            | Programmatically generate world variations    |
| **Marble Chisel**        | Control coarse 3D layout                      |
| **Marble Export**        | Splat/mesh output                             |
| **Omniverse / OpenUSD**  | Structure the simulation environment          |
| **Isaac Sim**            | Physics, sensors, cameras, robots             |
| **Synthetic Data tools** | Generate labeled CV datasets                  |
| **PyTorch/CV models**    | Train inspection models                       |
| **PharmaVerse**          | Orchestrate the complete research platform    |

This split is the architectural rule of the project:

* **Marble creates the world layer** — layout, appearance, spatial structure, and exportable geometry.
* **Isaac Sim creates the control layer** — physics, SimReady equipment, semantic labels, cameras, objects that can be spawned or moved, and inspection tasks.
* **PharmaVerse creates the research layer** — synthetic data, CV training, evaluation, Sim2Real, and later Physical AI.

Atlas is World Labs' omni world model. World Labs describes it as operating across text, images, camera poses, depth, and video, and as being designed around generation, reconstruction, and simulation of worlds. Atlas is also described as powering future versions of Marble.

Atlas is **not** the V1 dependency because it is not generally available:

* World Labs: **"Atlas is entering early access with select partners."**

This is better for the project than waiting. PharmaVerse can start building on Marble without Atlas access, while the architecture is explicitly designed to adopt Atlas later as a richer world-modeling and simulation backend.

# 7. Objective: World Generation with World Labs

The first major technical objective is **world generation with World Labs Marble**.

This is the defining first layer of PharmaVerse. The project does not begin by hand-modeling a pharmaceutical room, and it does not treat Marble as a convenience for concept art. Marble is the world-generation engine.

The V1 world-generation workflow is:

**Prompt / image / video / panorama / Chisel layout**

→ **Marble world generation**

→ **World editing / expansion as needed**

→ **Export Gaussian splats and meshes**

→ **Hand off to OpenUSD / Isaac Sim**

### Marble inputs

Marble can generate pharmaceutical worlds from:

* Text prompts
* Single images
* Multi-image input
* Video
* Panoramas / 360 captures
* Coarse 3D layouts through **Marble Chisel**

Chisel is the layout-control tool. It lets PharmaVerse specify a coarse 3D structure — for example a packaging room, conveyor line, inspection station, and staging area — while Marble supplies visual style and spatial detail. Structure and appearance can be separated: the same Chisel layout can yield multiple visual variants.

### World API

The World API is how PharmaVerse generates worlds programmatically rather than only through the Marble UI.

This matters because later experiments require many related environments, not one beautiful scene. The API can be used to:

* Generate a packaging-suite family from a shared prompt template
* Vary seeds and prompts for world-level domain randomization
* Produce digital cousins of a pharmaceutical area instead of one exact digital twin
* Drive repeatable generation as part of the PharmaVerse pipeline

World API generation is asynchronous: a generate request returns an operation, which is polled until the world is available.

### Marble exports

Marble worlds are useful to PharmaVerse only if they can leave Marble.

Primary exports:

* **Gaussian splats** — highest-fidelity visual representation of the generated world (PLY / SPZ)
* **Collider meshes** — low-fidelity triangle meshes intended for coarse physics simulation (GLB)
* **High-quality meshes** — higher-fidelity triangle meshes for interchange with standard 3D tools (GLB)

Gaussian splats carry appearance. Collider meshes carry coarse occupancy. Exact equipment physics, semantic labels, spawnable objects, and camera calibration are added later in Omniverse / Isaac Sim.

### What success looks like for this objective

A successful Marble phase produces:

* One or more navigable pharmaceutical packaging worlds
* Prompt and seed records for reproducibility
* Exported splat and mesh assets
* A documented generation recipe that the rest of the pipeline can repeat

The environment does not need to reproduce a specific commercial pharmaceutical facility. It should represent a plausible research environment containing common manufacturing and packaging elements, generated by Marble and then engineered for simulation.

Potential scene contents include:

* Conveyor systems
* Packaging stations
* Bottles
* Vials
* Cartons
* Labels
* Caps and closures
* Trays
* Bins
* Pallets
* Workstations
* Manufacturing equipment
* Doors and access points
* Material staging areas
* Inspection stations
* Operators
* Mobile inspection platforms

The objective is to create an environment that is not simply visually convincing but also **exportable, machine-readable, and ready for simulation preparation**.

# 8. Objective: Develop a Simulation-Ready OpenUSD Digital Twin

The Marble world is not yet a digital twin. After generation, the virtual environment will be prepared as an OpenUSD-based simulation environment.

Individual assets and scene elements should contain appropriate information such as:

**Object identity**

**Semantic class**

**Position**

**Orientation**

**Geometry**

**Collision properties**

**Material properties**

**Relationships with other objects**

This distinction is critical.

A Marble-generated 3D world may look like a pharmaceutical facility but still require engineering before it becomes useful for simulation. Marble supplies spatial structure and appearance. OpenUSD and Isaac Sim supply simulation semantics.

PharmaVerse will therefore use the workflow:

**World Labs Marble World**

→ **Splat / Mesh Export**

→ **NVIDIA Omniverse NuRec / USD Conversion**

→ **Geometry Cleanup**

→ **Semantic Labeling**

→ **Physics Configuration**

→ **SimReady Equipment and Controllable Objects**

→ **Simulation-Ready Environment**

Controllable objects that must be spawned, moved, occluded, or counted — bottles, cartons, labels, tools, documents — should be authored or imported as SimReady / USD assets in Isaac Sim rather than left as baked Marble appearance. Marble provides the room and spatial context. Isaac Sim provides the objects the inspection model must see, miss, or misclassify.

# 9. Objective: Create Virtual Computer Vision Sensors

PharmaVerse will deploy virtual cameras throughout the simulated facility in Isaac Sim.

Initial sensor configurations may include:

* Fixed RGB cameras
* Overhead cameras
* Angled inspection cameras
* Close-range inspection cameras
* Depth cameras

Future experiments may introduce:

* Stereo cameras
* LiDAR
* Robot-mounted cameras
* Mobile inspection cameras

Each virtual sensor should be configurable for characteristics such as:

* Resolution
* Field of view
* Camera angle
* Position
* Focal length
* Exposure
* Distance from target

This allows the project to investigate how **sensor placement affects computer vision performance** before physical hardware is deployed.

# 10. Objective: Generate Automatically Labeled Synthetic Data

A major objective of PharmaVerse is to generate synthetic training datasets directly from the simulation.

Because the simulator knows the identity and position of every object, it can produce ground truth automatically.

Potential annotations include:

* RGB images
* 2D bounding boxes
* 3D bounding boxes
* Semantic segmentation masks
* Instance segmentation masks
* Object IDs
* Depth maps
* Object poses
* Camera parameters

This removes much of the manual annotation burden associated with conventional computer vision dataset development.

Instead of manually drawing thousands of bounding boxes, PharmaVerse can generate:

**Scene**

*

**Image**

*

**Ground Truth**

simultaneously.

# 11. Objective: Implement Domain Randomization

One of the most important research components will be **domain randomization**.

PharmaVerse will deliberately modify conditions at two layers:

1. **World layer (Marble / World API)** — generate related pharmaceutical worlds with different layout, materials, and appearance.
2. **Simulation layer (Isaac Sim)** — vary lighting, cameras, object pose, occlusion, and spawned residuals inside a given world.

Variables may include:

### World generation

* Prompt phrasing
* Seed
* Chisel layout
* Visual style
* Room proportions
* Equipment arrangement implied by the generated world

### Lighting

* Brightness
* Direction
* Color temperature
* Shadows
* Reflections

### Camera

* Position
* Angle
* Height
* Focal length
* Exposure

### Objects

* Position
* Orientation
* Quantity
* Scale within realistic limits
* Occlusion

### Environment

* Equipment arrangement
* Surface appearance
* Background complexity
* Material placement

The objective is to prevent the CV model from learning one perfectly controlled virtual environment.

Instead, the model should encounter a distribution of possible environments.

# 12. First Demonstrator: Synthetic Line Clearance

The first PharmaVerse application will be:

## PharmaVerse Experiment 01

### Synthetic Pharmaceutical Line Clearance

A Marble-generated packaging/manufacturing area will be configured in Isaac Sim with a known expected cleared state.

The simulation will then programmatically introduce deviations.

Examples include:

* Previous-product bottle remaining
* Loose label remaining
* Incorrect carton
* Previous batch documentation
* Tool left on equipment
* Unidentified container
* Packaging component remaining
* Mixed materials
* Object partially hidden behind equipment
* Residual material at the edge of a camera's field of view

Because these scenarios are intentionally generated, the system automatically knows the ground truth.

For every simulated scene:

**Expected State**

vs.

**Actual State**

will be known.

# 13. Develop the Line-Clearance Computer Vision Model

Synthetic data generated by PharmaVerse will be used to train an initial computer vision model.

The model should identify relevant objects and potential discrepancies.

The workflow will be:

**Virtual Camera**

↓

**Image**

↓

**Object Detection / Segmentation**

↓

**Observed Objects**

↓

**Expected-State Comparison**

↓

**Potential Discrepancy**

↓

**Human Review**

Expected state: CLEAR

Potential discrepancy detected

Object: Previous-product carton

Zone: Conveyor exit

# 14. Sim2Real Research Objective

The most important experimental component of PharmaVerse will be determining whether synthetic data improves performance on real images.

Three experimental models should eventually be compared.

### Model A: Real-Only

Trained entirely on available real images.

### Model B: Synthetic-Only

Trained entirely using PharmaVerse-generated imagery.

### Model C: Synthetic + Real

Pretrained using a large synthetic dataset and fine-tuned using a smaller real dataset.

All models will then be evaluated against the **same held-out real-world test dataset**.

The experiment will answer:

> Does synthetic training data improve real-world computer vision performance while reducing the amount of manually collected and annotated real data required?

Evaluation should include:

* Precision
* Recall
* F1
* mAP
* IoU where appropriate
* False-positive rate
* False-negative rate
* Inference latency

---

# 15. Rare-Event and Edge-Case Simulation

A major advantage of PharmaVerse will be the ability to generate scenarios that are difficult to collect repeatedly in reality.

For example:

**Normal scenario**

Object completely visible.

**Moderate scenario**

Object partially obscured.

**Difficult scenario**

Small object mostly hidden behind equipment.

**Extreme scenario**

Object visible only from one camera under poor lighting.

Thousands of controlled variations can be generated.

The project can then answer questions such as:

> At what percentage of occlusion does detection reliability begin to decline?

> How does lighting affect false-negative rates?

> Which camera position provides the highest inspection coverage?

> How small can a residual object become before the model fails to detect it?

This converts PharmaVerse into an **AI testing environment**, not simply an AI training environment.

# 16. Physical AI Expansion

Once computer vision is functioning within the virtual facility, PharmaVerse can expand from passive inspection toward **Physical AI**.

A simulated mobile robot could be introduced into Isaac Sim, operating inside a Marble-generated pharmaceutical world.

The robot could use:

* RGB cameras
* Depth cameras
* LiDAR
* Computer vision
* Localization
* Path planning

Its objective would be to navigate through the simulated pharmaceutical manufacturing environment and inspect designated locations.

The architecture would become:

**Inspection Mission**

↓

**Autonomous Robot**

↓

**Navigate to Manufacturing Zone**

↓

**Acquire Visual Data**

↓

**Computer Vision Inspection**

↓

**Detect Potential Abnormality**

↓

**Record Location**

↓

**Generate Inspection Finding**

↓

**Human Review**

This would transform PharmaVerse from a synthetic-data project into a **Physical AI pharmaceutical manufacturing research platform**.

Atlas, if and when access is available, is the natural upgrade for richer world modeling, reconstruction, and simulation in this phase. It is not required to begin Physical AI experiments in Isaac Sim.

# 19. Recommended MVP

The initial PharmaVerse MVP should remain deliberately small, but it must include World Labs Marble as the world source.

### World generation

One pharmaceutical packaging suite generated with **World Labs Marble**, with splat and mesh export.

### Environment

That Marble world converted into one simulated pharmaceutical packaging room in OpenUSD / Isaac Sim.

### Assets

Approximately 10–20 relevant object types, authored as controllable simulation assets.

### Cameras

Two fixed virtual RGB cameras.

### Scenario

Line-clearance inspection.

### AI

One object detection or segmentation model.

### Synthetic Dataset

Approximately 5,000–10,000 automatically labeled images.

### Experiment

Evaluate detection performance across normal, residual-object, occlusion, lighting, and camera-position scenarios.

### Final MVP Demonstration

The user launches a PharmaVerse simulation built from a Marble-generated packaging world.

A packaging station initially appears cleared.

The simulation introduces a previous-product component.

A virtual camera observes the scene.

The CV model detects the object.

The interface highlights it.

The system reports:

**REVIEW REQUIRED**

Potential residual material detected.

The user can then change the lighting, object position, camera angle, or occlusion level and observe whether the model continues to detect the discrepancy.

# 20. Long-Term Vision

The long-term vision is for PharmaVerse to become a reusable **virtual AI proving ground for pharmaceutical manufacturing**.

Rather than requiring every new AI concept to begin with physical hardware, manufacturing access, and real-world data collection, researchers could first develop and evaluate the concept inside PharmaVerse.

The progression becomes:

**Generate with World Labs**

→ **Simulate in Omniverse / Isaac Sim**

→ **Train**

→ **Test**

→ **Stress-Test**

→ **Validate Against Real Data**

→ **Improve**

→ **Potential Physical Deployment**

Near-term, that generation step is **Marble + World API**.

Later, that generation and simulation step can become **Atlas**, if access and product integration allow it.

Ultimately, PharmaVerse will investigate whether **World Labs world models, OpenUSD digital twins, synthetic data, computer vision, NVIDIA simulation, and Physical AI can provide a practical development environment for next-generation pharmaceutical manufacturing intelligence.**
